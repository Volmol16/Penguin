# Step 5: wake word + глазки вместе (ещё без WiFi)

Объединение Step 3 (детектор "Ирина" на реальном микрофоне) и Step 4
(диагностика при старте + анимированные глазки на OLED) в одной прошивке.
WiFi/OTA/сервер — следующий шаг (Step 6), здесь всё ещё работает полностью
автономно.

## Архитектура

Две задачи FreeRTOS на разных ядрах ESP32-S3:

- **wakeWordTask (ядро 1)** — читает I2S-микрофон, инференс TFLM. Не трогает
  экран.
- **eyesTask (ядро 0)** — ~30 раз/сек перерисовывает глаза. При детекте
  wake word (сигнал через `s_wake_event`) на 1.5с переключает эмоцию на
  SURPRISED и моргает, потом возвращается в NEUTRAL.

Экран трогает только `eyesTask` — поэтому не нужен мьютекс на framebuffer.

## Перед сборкой обязательно

1. Впишите ОБЕ группы пинов в `main/main.cpp`: `WW_I2S_*` (микрофон, как в
   Step 3) и `OLED_*` (экран, как в Step 4). Если вы уже собирали Step 3 и
   Step 4 по отдельности на этой же плате — просто скопируйте те же номера,
   которые уже сработали там.
2. Сгенерируйте `main/wake_word_model.h` из `irina.tflite` (как в Step 3):
   ```
   python tools/tflite_to_header.py irina.tflite --name "Ирина" -o main/wake_word_model.h
   ```
3. Octal PSRAM в menuconfig (как во всех предыдущих шагах).

## Сборка

```
pio run
pio run --target upload
pio device monitor
```

## Что проверять

- На экране по очереди `SPEAKER/WIFI/SERVER: OK` (заглушки, см. `TODO` в
  коде — реальные проверки появятся в Step 6), потом глазки.
- Глазки моргают сами по себе (как в Step 4).
- Скажите "Ирина" — глаза должны на 1.5 секунды стать больше (SURPRISED) и
  моргнуть, затем вернуться в обычное состояние. В логе — `>>> WAKE WORD
  DETECTED <<<`.
- Если глаза не реагируют, но в логе детект есть — проблема в передаче
  события между задачами (маловероятно, логика простая) или глаза просто не
  видны из-за неподогнанных координат (см. калибровку в Step 4 — те же
  команды работают и здесь, калибровка не была перенесена в этот файл
  отдельно, допишите при необходимости по образцу Step 4's `main.cpp`).
